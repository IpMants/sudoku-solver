# Quickstart: Validating the Sudoku Solver Feature

This guide describes how to run the app locally and manually (or via e2e tests)
validate that each user story from `spec.md` works end-to-end. It intentionally
does not include implementation code — see `data-model.md` and `contracts/` for
the internal shapes, and `tasks.md` (generated by `/speckit-tasks`) for build
steps.

## Prerequisites

- Node.js LTS and npm installed.
- Angular CLI available (`npx ng version` should work via the project's
  `devDependencies` once scaffolded).
- Repository dependencies installed: `npm install` from the repo root.

## Running the app

```powershell
npm start
# or: npx ng serve
```

Then open the printed local URL (typically `http://localhost:4200`) in a
browser. No login or account setup is required (FR-008).

## Running automated tests

```powershell
# Unit/component tests (solver, validator, components) - Constitution Principle III
npm test
# or: npx ng test

# End-to-end user-story tests
npm run e2e
```

## Manual / e2e validation scenarios

Each scenario below maps to a user story and its acceptance scenarios in
`spec.md`; automate these as e2e tests where practical.

### Scenario 1 — Instantly solve the default puzzle (User Story 1, P1)

1. Open the app fresh (no prior interaction, e.g., a new private/incognito
   window).
2. **Expect**: within ~1 second, a sudoku grid is already displayed with some
   given digits filled in — no login prompt, no empty-state screen requiring
   setup (SC-001).
3. Click **Solve All**.
4. **Expect**: within ~2 seconds, every cell is filled and the grid shows a
   fully valid classic sudoku solution (no row/column/box has a repeated digit)
   (SC-002).
5. Reload the page.
6. **Expect**: a puzzle is shown again immediately, still with no login/sign-in
   required.

### Scenario 2 — Choose a specific example puzzle (User Story 2, P2)

1. With any puzzle displayed, open the example puzzle picker.
2. **Expect**: at least 5 distinct example puzzles are listed, spanning more
   than one difficulty label (SC-006).
3. Select an example different from the one currently shown.
4. **Expect**: the board immediately updates to that puzzle's given digits only
   (no leftover digits from the previous puzzle).
5. Click **Solve All**.
6. **Expect**: the selected puzzle solves correctly, as in Scenario 1 step 4.
7. Re-select the same example puzzle again.
8. **Expect**: the board resets to that puzzle's original given digits (Edge
   Cases).

### Scenario 3 — Enter a custom puzzle from scratch (User Story 3, P3)

1. Choose the "enter your own puzzle" option.
2. **Expect**: an empty 9x9 grid is presented, ready for digit entry.
3. Type in the given digits of a known, valid classic sudoku puzzle (from any
   external reference).
4. **Expect**: no conflicts are flagged as you type valid digits.
5. Type a digit that duplicates another digit already in the same row, column,
   or 3x3 box.
6. **Expect**: the conflict is highlighted immediately (in real time, before
   clicking any solve button) (FR-004, SC-004).
7. Correct the conflicting digit, then click **Solve All**.
8. **Expect**: the puzzle solves correctly.
9. Start a new custom puzzle and enter given digits that are known to make the
   puzzle unsolvable, then click **Solve All**.
10. **Expect**: a clear message states no solution exists; the app does not
    freeze or crash (FR-007, SC-007).

### Scenario 4 — Reveal the solution one digit at a time (User Story 4, P2)

1. With any valid puzzle loaded (default, example, or custom) and at least one
   empty cell remaining, click **Solve Next Digit**.
2. **Expect**: exactly one previously empty cell becomes filled with a correct
   digit within ~1 second; all other cells remain unchanged (SC-003).
3. Repeat clicking **Solve Next Digit** until no empty cells remain.
4. **Expect**: the final grid matches what **Solve All** would have produced
   for the same starting puzzle.
5. Click **Solve Next Digit** once more on the now fully-solved puzzle.
6. **Expect**: no error occurs and the app indicates the puzzle is already
   complete (no destructive change to the board).

### Scenario 5 — Reset a puzzle

1. With any puzzle partially or fully solved, trigger the reset action.
2. **Expect**: the board returns to that puzzle's original given digits only,
   discarding any solver-filled or user-entered digits (FR-009).
3. With an example puzzle displayed, manually type a digit into one of its
   empty (non-given) cells without using a solve action, then trigger reset.
4. **Expect**: that manually entered digit is cleared back to empty, leaving
   only the example's original given digits (FR-009).
5. With a custom puzzle being entered from scratch (some given digits typed
   in, none via an example), trigger reset.
6. **Expect**: the board returns to a fully empty 9x9 grid, since a
   from-scratch custom puzzle has no original given digits of its own
   (FR-009).

### Scenario 6 — See which cell is about to be changed (User Story 5, FR-013)

1. With any puzzle displayed, click a cell.
2. **Expect**: that cell is visually marked as selected.
3. Click a different cell.
4. **Expect**: the marking moves to the newly clicked cell; the previously
   selected cell no longer shows it (never more than one selected at once).
5. Use arrow-key keyboard navigation to move focus to another cell.
6. **Expect**: the selection marking follows keyboard focus.
7. With a cell selected, click **Solve Next Digit** so that the selected cell
   (or another cell) gets filled by the solver.
8. **Expect**: if the selected cell was the one filled, it remains visibly
   selected afterward.
9. Select a different example puzzle, or start a custom puzzle, or reset.
10. **Expect**: no cell appears selected on the newly displayed board until the
    user makes a new selection (Edge Cases).

### Scenario 7 — Discover the live demo and project provenance via README (User Story 6, FR-014/FR-015)

1. Open the repository's `README.md` (e.g., on GitHub).
2. **Expect**: a link to the deployed demo at
   `https://ipmants.github.io/sudoku-solver/`.
3. Click the demo link.
4. **Expect**: the deployed Sudoku Solver application opens successfully.
5. **Expect**: a statement that the project was generated completely with AI
   (GitHub Copilot) using a Spec-Driven Development (SDD) approach with the
   GitHub Spec Kit framework, with a working link to
   `https://github.github.com/spec-kit`.

## Success criteria checklist

Use this checklist alongside the scenarios above to confirm the feature meets
`spec.md`'s Success Criteria:

- [X] SC-001: Default puzzle visible within ~1s of load, no setup steps.
- [X] SC-002: "Solve All" completes a valid puzzle within ~2s.
- [X] SC-003: Each "Solve Next Digit" click resolves within ~1s, repeatable at
      least 50 times on one puzzle without error.
- [X] SC-004: Every rule-conflicted puzzle is flagged before any solve action
      changes the board.
- [X] SC-005: No authentication step is ever presented.
- [X] SC-006: At least 5 example puzzles across multiple difficulties are
      available.
- [X] SC-007: Every unsolvable puzzle produces a clear message, never a hang or
      crash.
- [X] SC-008: Exactly zero or one cell is ever shown as selected, and the
      selected cell is identifiable within ~1s of clicking/navigating to it.
- [X] SC-009: `README.md`'s live demo link is locatable and opens the working
      application within ~10s of reading.
- [X] SC-010: `README.md`'s AI/SDD provenance statement and Spec Kit link are
      locatable within ~10s of reading.

All ten success criteria were validated by the automated suite in
`e2e/sudoku-solver.spec.ts` (Scenarios 1-6, run via `npm run e2e`) alongside
the unit/component suite (`npm test`) — Scenarios 1-5 as part of
`/speckit-implement`'s Phase 7 (T038-T039), Scenario 6 (SC-008) as part of
Convergence T048, and Scenario 7 (SC-009/SC-010) validated by manual
inspection of the rendered `README.md` (documentation-only, not covered by
`e2e/sudoku-solver.spec.ts`).
